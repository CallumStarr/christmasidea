# Prioritised assurance roadmap

This is an operator-reviewed sequence, not authority to deploy, spend money,
enable providers or change accounts. Effort and commercial returns are not
estimated without team/account evidence.

## Before the next release

1. Review the 20 repaired findings, unchanged feature flags and additive client
   contracts; run required remote CI under protected main/release controls.
2. Privately verify required Turnstile settings, secret scope and IP-salt entropy.
   Confirm old-client compatibility in a staged environment.
3. Obtain privacy/legal decisions on input-derived PII/cache handling, recent-item
   storage and Insights, audience/children and online-safety scope.
4. Resolve eBay attribution intent and merchant/account approval. Keep other
   dormant integrations off; do not represent inactive inventory as approved.
5. Run iOS compilation and Android/iOS minimum/current-device checks, manual
   assistive-tech/contrast/zoom testing and safe-area/keyboard lifecycle flows.

## Next engineering iteration

1. Add request-cancellation/provider-cost regression coverage and a bounded
   propagation design with reservation consistency.
2. Establish observable SLOs, privacy-safe diagnostics, dependency failure alerts,
   quota dashboards and non-production restore/rollback exercises.
3. Inventory inline script/style requirements and stage progressively tighter CSP.
   Review the entire controlled subdomain inventory before changing HSTS scope.
4. Extend product hard-constraint adversarial fixtures with ambiguous variants,
   bundles, condition conflicts, out-of-stock/expiry and subscription commitments.
5. With explicit cost approval, run the 24 added scenarios against frozen baseline
   and candidate configurations using independent blinded reviewers. Keep
   deterministic CI separate from paid benchmarks.

## Before any dormant integration or learning activation

1. Obtain merchant/provider contracts, feed/image permissions, territory, tracking
   and actual quota/commission evidence.
2. Reimport and validate Awin data with the repaired condition/allowlist rules in
   isolation; prove freshness, retention and restoration before activation.
3. Verify signed evidence support, independent-human limitations, cohort thresholds,
   policy approval/expiry/provenance and rollback. Self-reported purchases remain
   self-reported; receipt possession is not unique-person verification.
4. Record a separately approved release with measured product and privacy gates.
   A newer engine or higher aggregate score alone is not sufficient.

## Ongoing

Maintain immutable-action/dependency updates, redacted secret scanning, release
SBOM/provenance, native SDK/store reviews, meaningful user-quality evaluation,
small-cohort/retention reviews and documented incident exercises. Reassess the
scope after new accounts, cloud lists, advertising, user-to-user content or model
tools are added; this audit's assumptions would then materially change.
